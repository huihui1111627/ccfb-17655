# certrot — 证书轮换传播模拟器

用 Go 在本地**真实文件系统**上复现集群证书轮换的完整链路:apiserver 的 Secret 对象 →
节点 kubelet 的挂载更新机制 → 容器内应用的各种证书读取方式,并对静态扫描预判与实测结果
做逐容器比对。

所有证书都是用 `crypto/x509` 真实签发的 ECDSA 证书;所有挂载/读取都在本地磁盘上真实执行;
文件监听使用真实的 [fsnotify](https://github.com/fsnotify/fsnotify)(Linux 上即 inotify)。

## 它复现的故障

| 层 | 模式 | 轮换后行为 |
|---|---|---|
| kubelet 挂载 | 整卷 secret/projected 挂载 | 节点同步后用**原子写入器**更新:写新时间戳目录 → `..data_tmp` 符号链接 → `rename` 原子切换 `..data` |
| kubelet 挂载 | `subPath` 单文件挂载 | 启动时 bind 的文件**永不更新**,只有重建 Pod/重启容器 |
| 容器运行时 | 环境变量注入 | 启动时渲染一次,Secret 后续变化与进程内变量无关 |
| 应用 | 启动只读一次 | 磁盘已换新证,进程内存里永远是旧证 |
| 应用 | 定时重读 | 节点同步 + 一个轮询周期内自动换证 ✅ |
| 应用 | 监听文件路径 | inotify 钉在旧 inode 上,`..data` 切换对文件路径无事件,**永不触发** |
| 应用 | 监听挂载目录 | 能收到符号链接切换事件,触发重读 ✅ |
| 应用 | 监听目录但只认证书文件名的事件 | 切换事件名是时间戳目录/`..data`,被过滤器丢弃,**永不触发** |
| 应用 | 轮询 + 目录监听组合 | 双保险,任一先触发即换证 ✅ |

> 平台说明:macOS 的 kqueue 后端在符号链接链切换时会合成 REMOVE/CREATE 事件,与 Linux
> inotify(钉住解析后的 inode、切换时无事件)不同。`app` 包在 fsnotify 之上显式实现了
> inotify 语义(inode 身份钉定、目录条目变更校验),保证模拟结论与线上 Linux 行为一致,
> 且底层事件仍全部来自真实 fsnotify。

## 目录结构

```
certs/   真实 ECDSA CA 与叶子证书签发、PEM/base64 解析、指纹
store/   apiserver 模拟:多版本 Secret 对象与资源版本(RV)
node/    kubelet 模拟:周期同步、原子写入器(..data 切换)、subPath、env 注入、GC
app/     容器内进程:6 种读取/监听策略,真实 goroutine + fsnotify
cluster/ 几百个工作负载的混合舰队生成器(含多容器组合 Pod)
scan/    轮换前静态扫描:每个容器能否自动换证、延迟上界、故障分层
plan/    轮换计划:重叠期建议、重启批次与顺序(跨节点打散、按等级排序)
sim/     编排:独立磁盘核验、时间序列采样、到期翻转、预判 vs 实测比对报告
web/     HTTP API + 内嵌单页仪表盘(无外部依赖,离线可用)
```

## 运行

### 仪表盘模式(默认)

```bash
go run . -addr :8080 -workloads 320 -nodes 8 -old-ttl 3m
# 打开 http://localhost:8080
```

页面上可:
- 查看每个工作负载/容器的**挂载方式、读取方式、静态预判、进程加载版本、磁盘核验版本**;
- 点「执行轮换」后观察**新/旧证书使用比例随时间的曲线**(含磁盘独立核验虚线、
  轮换时刻与旧证到期时刻标注);
- 「到期前还没换上的清单」实时交叉核验预判与实况;
- 按计划批次执行重启,或在容器详情里单独重启;
- 生成**预判 vs 实测比对报告**(一致 / 漏判 / 误判 / 超延迟上界 / 重启后换上)。

### Headless 演示模式

自动执行 扫描 → 轮换 → 等待自动换证 → 比对 → 分批重启 → 终态核验,输出 JSON 报告:

```bash
go run . demo -workloads 320 -nodes 8 -old-ttl 3m
# 报告写到 $TMPDIR/certrot-data/rotation-report.json
# 任一漏判/误判/未全部换上 v2 时进程以非零码退出
```

实测一次的结果(320 工作负载 / 362 容器):自动换证 76 个,计划重启治愈 286 个,
**漏判 0、误判 0、超延迟上界 0**;自动换证实测延迟 3.3s–29.0s,静态上界最大 42s。

### 测试

```bash
go test ./...
```

- `sim/matrix_test.go`:全部 14 种合法 挂载×读取 组合的确定性矩阵验证 + 重启恢复;
- `sim/expiry_test.go`:旧证到期翻转、轮换恢复、重启恢复;
- `node/node_test.go`:原子写入器磁盘布局、旧目录 GC、subPath/env 冻结与重启重渲染;
- `scan/scan_test.go`:静态预判判定表与延迟上界。

## 静态扫描的延迟上界模型

对可自动换证的容器,最坏延迟 = 节点同步周期 × 1.2(模拟节点抖动)+ 应用重读间隔
(轮询为 ticker,目录监听为事件 + 150ms 去抖)。舰队取所有容器的 P50/P95/Max。

## 轮换计划规则

- 最小重叠期 = 全网最大延迟上界 + 10s(覆盖一次错过同步);
- 建议重叠期 = 最大上界 × 2 + 30s(值班介入与批次执行窗口);
- 必须重启的容器分 6 个/批,批内跨节点打散,顺序为 一般业务 → 中间层 → 核心基础设施;
- subPath 与环境变量故障在挂载/运行时层,改应用代码无法补救,只能重建 Pod。
